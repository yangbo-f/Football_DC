# 足球 Dixon-Coles 模型精度提升路线

## 当前基础模型

当前工具使用 Dixon-Coles 进球模型，核心输入是历史比赛的 90 分钟比分。模型会从历史比分中拟合每支球队的进攻强度、防守强度、普通主场优势，以及低比分相关修正参数。

当前默认使用方式：

- 世界杯模式会合并 `WorldCup` 正赛和 `WorldCupQualifiers` 预选赛周期训练。
- 2026 世界杯正赛数据已保留 `stage/round`，可区分小组赛和淘汰赛。
- 当前已经加入基础训练权重：世界杯正赛 `1.00`，正赛淘汰赛 `1.05`，世界杯预选赛 `0.45`。
- 当前已经加入第一版跨赛区强度校正：用 `data/worldcup/team_strength_ratings.csv` 或内置先验提供 `team/confederation/rating`，双方赛区不同时在预测阶段小幅修正 expected goals。
- 英超、中超、世界杯仍按赛事体系分别训练，不把国家队和俱乐部赛事混在一个普通模型里。
- 预测输出是 90 分钟常规时间概率，包括胜平负、比分、大小球、双方进球、让球胜平负、亚洲让球等。
- 当前不输出晋级概率。淘汰赛的“平局”表示 90 分钟打平，不表示最终晋级。
- 赔率只用于市场对比、去水概率、期望收益（EV）和融合概率，不进入历史训练。
- 人工判断只作用于本场预测的期望进球，不改历史数据和球队参数。

## 数据文件规范

世界杯长期按“每届正赛 + 对应预选赛周期”维护：

- `data/worldcup/finals_2026.csv`
- `data/worldcup/qualifiers_2026_cycle_all.csv`
- `data/worldcup/finals_2022.csv`
- `data/worldcup/qualifiers_2022_cycle_all.csv`
- `data/worldcup/finals_2018.csv`
- `data/worldcup/qualifiers_2018_cycle_all.csv`

俱乐部联赛按赛事和赛季维护：

- `data/epl/epl_2025_2026.csv`
- `data/csl/csl_2026.csv`

建议所有比赛 CSV 尽量包含这些字段：

```text
competition,season,date,home_team,away_team,home_goals,away_goals,neutral_site,stage,round,score_basis,decided_by_penalties,winner,notes
```

其中 `home_goals` / `away_goals` 应优先填写 90 分钟常规时间比分。`score_basis` 推荐使用 `FT90`；如果数据源写成 `full_time`，当前工具会按 `FT90` 处理。

## 什么进入训练

适合进入 Dixon-Coles 历史训练：

- 90 分钟常规时间比分。
- 比赛日期。
- 主队、客队。
- 是否中立场。
- 赛事类型和赛季。

不建议直接进入 Dixon-Coles 历史进球训练：

- 点球大战比分。
- 晋级球队。
- 赔率。
- 赛前主观判断。
- 临场伤病、轮换、战意备注。

这些信息可以展示、记录，或者作为预测阶段修正，但不要写进 `home_goals` / `away_goals`。

## 近期最值得做的精度提升

1. 补齐历史数据

   世界杯至少补齐 2018、2022、2026 正赛和对应预选赛周期。英超和中超建议补 3 到 5 个完整赛季。数据越完整，球队攻防参数越稳定。

2. 做数据质量检查

   增加页面或脚本检查空比分、重复比赛、未知球队名、非 FT90 比分、中立场缺失、日期异常。模型精度首先取决于数据是否干净。

3. 调整时间衰减

   默认半衰期 365 天适合起步。世界杯国家队样本稀疏，可以测试 540 天、730 天；联赛可以测试 180 天、365 天。用回测结果决定默认值。

4. 增加赛事权重

   世界杯正赛、预选赛、友谊赛的重要性不同。当前已做第一版权重：正赛高于预选赛。后续需要用回测验证 `0.45` 是否合适，并可按不同赛区、比赛轮次和对手强弱继续细分。

5. 增加阶段权重

   小组赛和淘汰赛的比赛动机、风险偏好不同。Dixon-Coles 不会自动知道这些阶段差异，需要人工设定阶段权重或进球修正，并用回测验证。一个起步方案是：正赛权重大于预选赛；淘汰赛保留正赛权重，但在预测阶段额外测试总进球 -5% 到 -10% 的修正。

6. 单独处理东道主

   世界杯正赛通常是中立场，但东道主不是普通中立队。后续可以增加东道主修正，和普通主场优势分开。

7. 建立回测页

   用历史比赛滚动训练、预测下一场，再计算胜平负准确率、Brier Score、Log Loss、大小球命中率和 EV 表现。没有回测，就很难判断改动是否真的提升精度。

## 中期增强方向

1. Elo 辅助模型

   国家队和俱乐部分别维护 Elo。Elo 可以提供球队整体强弱和近期趋势，用来和 Dixon-Coles 概率融合。国家队尤其需要 Elo 或类似强度层，因为亚洲区预选赛、非洲区预选赛、欧洲区预选赛不能直接用同一强度口径比较。当前版本的 `team_strength_ratings.csv` 是第一版权重先验，后续应替换或校准为真实 Elo/FIFA ranking。

2. xG 和射门数据

   如果能获取 xG、射门、射正、禁区触球等数据，可以比单纯比分更早反映球队真实表现。

3. 阵容和伤病

   伤病、停赛、轮换应先作为预测阶段修正。比较稳的做法是影响本场期望进球，例如主队进攻 -8%、客队防守 -5%。球星变量要单独处理，不能只做普通备注；例如萨拉赫这类单点影响大的球员，需要结合出场概率、位置、进攻参与度和球队依赖度转成 expected goals 修正。

4. 体能和赛程

   加入休息天数、连续客场、长途旅行、加时赛后短休等变量。世界杯和联赛都可能明显受影响。

5. 赔率融合校准

   市场赔率通常包含大量信息。建议保留纯模型概率，同时用去水市场概率做融合概率。融合权重需要靠回测确定，不应凭感觉固定。

## 长期方向

- 增加自动赔率接口，但 API key 只保存在本地配置，不写进 git。
- 增加自动赛程和最新赛果更新。
- 做多模型对比：纯 Dixon-Coles、人工修正、赔率融合、Elo 融合。
- 增加概率校准层，修正长期高估强队、低估平局等系统偏差。
- 增加淘汰赛晋级概率模块。它应基于 90 分钟概率、加时/点球假设、双方点球能力和市场信息单独计算，不能和 90 分钟胜平负混为一谈。
- 保存每次预测快照，后续对照真实赛果复盘。

## 当前明确限制

- 跨赛区国家队强度已经有第一版预测阶段校正，但还不是完整 Elo 模型。亚洲区和非洲区等不同赛区仍需要真实 Elo、FIFA ranking、跨赛区正赛交手或洲际附加赛作为锚点。
- 当前主要使用进失球，不使用 xG/xGA、射门质量、创造机会质量。
- 未参赛不是负样本。比如埃及缺席 2022 正赛，不应被当成失败比赛写入模型；如果埃及只有预选赛数据，模型只能基于预选赛样本估计，置信度应低于有正赛样本的球队。
- 球星变量尚未结构化。当前人工修正可以手动调 xG，但还没有球员级数据、出场概率和球队依赖度模型。
- 当前输出的是 90 分钟赛果概率，不是晋级概率。

## 当前优先级建议

第一优先级是补齐数据和回测。模型参数、赔率融合、人工修正都应该用回测验证。没有回测之前，不建议大幅调整复杂权重，否则容易让页面看起来更复杂，但预测未必更准。
